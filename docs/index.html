Shamba Direct API (1.0.0)

Download OpenAPI specification:

Farmer-to-buyer produce marketplace API for Kenya (Express + MySQL). Farmers list produce; buyers (companies) browse, enquire, order and rate.

Quickstart

Start the API locally (see the README), then:

curl http://localhost:5000/api/products

No account or token is needed — that call returns the seeded produce listings.

Authentication

There is no token authentication yet. Every endpoint is currently public: no Authorization header is required or checked. POST /api/auth/login verifies a phone number + password and returns the user's profile, but it does not return a token or start a session. Callers identify themselves by sending ids in the request body (farmerId, buyerId). Real authentication arrives in Week 9; this section will change then.

Conventions

  • Request and response bodies are JSON. Write requests must send Content-Type: application/json.
  • Field names in requests are camelCase (pricePerKg); field names in responses are snake_case (price_per_kg) because they come straight from the database.
  • MySQL DECIMAL values (prices, quantities, coordinates) are serialized as strings, e.g. "45.00".
  • Timestamps are ISO-8601 UTC strings.

Errors

Every failed request returns a JSON body with a single error string. Success bodies never contain an error key — they carry a message (and usually an id). Status codes used: 400 bad/missing input, 401 bad credentials, 404 unknown record or route, 409 duplicate account, 500 server/database failure.

{ "error": "Listing not found" }

Malformed requests and wrong URLs use the same shape:

Mistake Response
Body is not valid JSON 400 { "error": "Request body is not valid JSON" }
Forgot Content-Type: application/json (body ignored) 400 { "error": "<field>, <field> are required" }
URL does not exist 404 { "error": "Route not found: GET /api/nope" }
